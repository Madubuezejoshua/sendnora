SENDNARO - TELEGRAM & WHATSAPP DELIVERY GUIDE
================================================

PART 1. WHAT THIS DOES
----------------------
Sendnaro can deliver invoice links (and payment reminders) to a customer over
two chat channels, in addition to email.

  WhatsApp  Level 1  "Click-to-chat": always on, needs NO credentials. The app
                     builds a wa.me link with a pre-filled message; the staff
                     member taps it and sends from their own WhatsApp.
            Level 2  "Meta Cloud API": automatic sending + delivery-status
                     callbacks. Built, but INACTIVE until Meta credentials
                     are added (see Part 5). Not yet tested live.

  Telegram           Automatic sending from the shared bot @Invoicetapbot.
                     Live and tested. Telegram bots cannot message a person
                     first, so each customer must connect once (Part 3).


PART 2. USING IT DAY TO DAY (for a business owner / staff member)
-----------------------------------------------------------------
1. Log in at https://sendnaro-web.vercel.app and select your workspace.
2. Add the customer (Customers > New). For WhatsApp, fill the "WhatsApp
   number" field with the full international number (e.g. +234 801 234 5678).
3. Create an invoice (Invoices > New invoice), save it, then click
   "Issue invoice". The invoice page now shows a public link plus two buttons.

   WHATSAPP:  click "Share via WhatsApp". WhatsApp opens with the message and
              invoice link ready; press Send.

   TELEGRAM:  click "Send via Telegram".
     - If the customer is already connected, the invoice link is sent to their
       Telegram instantly and you see "Sent via Telegram".
     - If NOT yet connected, you get a one-time link (it is also copied to
       your clipboard). Send that link to the customer by any means (SMS,
       WhatsApp, email). Details in Part 3.

4. The customer opens the invoice link, views it, and can pay online
   (Paystack / Flutterwave). The invoice status updates automatically and a
   receipt is generated.


PART 3. HOW A CUSTOMER CONNECTS TELEGRAM (one time only)
--------------------------------------------------------
1. The customer taps the one-time link, which looks like
      https://t.me/Invoicetapbot?start=<code>
2. Telegram opens the bot. They press START.
3. The bot replies "Hi <name>! You'll now receive your invoices..." - they are
   now connected. The one-time code is used up and cannot be reused.
4. From then on "Send via Telegram" delivers straight to their chat.
5. The customer can type /stop to the bot at any time to opt out. After that,
   sending fails with "not linked" until they connect again via a new link.

Notes
  - One shared bot (@Invoicetapbot) serves every business on the platform.
  - Telegram needs the customer's own action; we never see a phone number.
  - Payment reminders: the reminder engine supports a TELEGRAM channel, but the
    default reminder schedule created at invoice issue time uses EMAIL, and
    there is no screen yet to choose Telegram. (Planned: a per-workspace
    reminder-channel setting.)


PART 4. HOW IT WORKS (for developers)
-------------------------------------
Files (all under apps/api/src unless noted)
  services/telegram/telegram.service.ts   send, deep-link creation, /start & /stop
  modules/telegram/telegram-webhook.routes.ts   POST /api/v1/webhooks/telegram
  modules/invoices/invoice-telegram.service.ts  builds the invoice message
  modules/reminders/reminders.service.ts        TELEGRAM reminder branch
  services/whatsapp/*                           click-to-chat + Meta adapter
  modules/whatsapp/whatsapp-webhook.routes.ts   Meta handshake + status callbacks
  ../web/src/components/app/telegram-share-button.tsx   the UI button

Database (packages/database/prisma, migration 20261011000000_telegram_channel)
  Customer.telegramChatId, Customer.telegramLinkToken (unique, single use)
  MessageChannel enum now includes TELEGRAM
  Every send is recorded in MessageDelivery (QUEUED -> SENT / FAILED).

API endpoints (bearer token from the web app; workspace comes from the token)
  POST /api/v1/customers/:customerId/telegram-link   -> { url, linked }
  POST /api/v1/invoices/:invoiceId/send-telegram     -> { sent: true }
        or { sent:false, reason:'not_linked', linkUrl } | 'not_configured' | 'send_failed'
  POST /api/v1/webhooks/telegram        (called by Telegram only; header
        X-Telegram-Bot-Api-Secret-Token must equal TELEGRAM_WEBHOOK_SECRET,
        otherwise 401)

Security properties
  - Webhook is fail-closed: with no secret configured every call is rejected.
  - Deep-link codes are random, single-use, and workspace-scoped lookups mean a
    user can never link or message another workspace's customer
    (covered by tests/integration/telegram.test.ts).
  - Errors inside the webhook still return 200 so Telegram does not retry-loop.


PART 5. ADDING IT TO SOMEONE ELSE'S SYSTEM / ENVIRONMENT
--------------------------------------------------------
There are three ways to put Sendnaro to work for another business. Pick one.

OPTION A - Give them a workspace on your hosted install (simplest)
  1. They register at /register and verify their email.
  2. Onboarding creates their workspace; they add their business profile,
     customers and invoices. Telegram and WhatsApp click-to-chat work
     immediately - nothing to install, because the bot and the platform are
     already running for everyone.
  3. Invite their team under Settings > Team.
  4. Connect their payment provider(s) so customers can pay (Paystack /
     Flutterwave keys are stored encrypted per workspace).

OPTION B - Deploy their OWN copy (white-label / separate data)
  Requirements: a Vercel account, a Neon (Postgres) database, optionally
  Backblaze B2 (files), Resend (email), Paystack/Flutterwave (payments).

  1. Get the code and install:            npm ci
  2. Create a Neon database; copy its pooled and direct (unpooled) URLs and
     add  connect_timeout=30  to both (Neon wakes slowly after idle).
  3. Fill .env (see .env.example and ENVIRONMENT.md). Minimum:
       DATABASE_URL, DIRECT_DATABASE_URL
       AUTH_SECRET, API_TOKEN_SECRET, APP_ENCRYPTION_KEY, CRON_SECRET
           (each: openssl rand -base64 32)
       NEXT_PUBLIC_APP_URL, NEXT_PUBLIC_API_URL, API_INTERNAL_URL, CORS_ORIGINS
       SEED_ADMIN_EMAIL, SEED_ADMIN_PASSWORD   (12+ chars, no '#')
  4. Create the tables and seed:
       npm run db:migrate:deploy --workspace=@sendnaro/database
       npm run db:seed --workspace=@sendnaro/database
  5. Create two Vercel projects from the same repo:
       sendnaro-api  -> root directory apps/api   (has its own vercel.json)
       sendnaro-web  -> root directory apps/web   (has its own vercel.json)
     Add the environment variables to each, then deploy each with
       vercel deploy --prod
     (API needs the DB, secrets, B2, email and payment keys; WEB needs the DB,
     the three secrets, and the URLs.)
  6. Verify:  <api-url>/health returns {"status":"ok"} and /ready returns
     {"status":"ready"}.

  TELEGRAM for their own deployment
    a. In Telegram open @BotFather, send /newbot, choose a name and a username
       ending in "bot". Copy the token it gives you.
    b. Add to the API project's environment:
         TELEGRAM_BOT_TOKEN       = <token from BotFather>
         TELEGRAM_WEBHOOK_SECRET  = <random string, e.g. openssl rand -hex 24>
       then redeploy the API.
    c. Register the webhook (run once; replace the three values):
         curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
              -d "url=<API_URL>/api/v1/webhooks/telegram" \
              -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>" \
              -d 'allowed_updates=["message"]'
       Check:  curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
       (the url must match and last_error_message must be empty).
    d. Open the bot, press Start, then test with a customer as in Part 3.

  WHATSAPP (Meta Cloud API) for their own deployment - optional
    Click-to-chat already works with no setup. For automatic sending:
    a. developers.facebook.com/apps > Create App > Business > add the
       "Connect with customers through WhatsApp" use case (needs a Meta
       Business portfolio).
    b. WhatsApp > API Setup gives you the Phone number ID and WhatsApp
       Business Account ID. Create a system user in Business settings and
       generate a permanent token (whatsapp_business_messaging +
       whatsapp_business_management). App settings > Basic gives the App
       secret. Invent any random string as the verify token.
    c. Set in the API environment:
         WHATSAPP_PROVIDER=meta-cloud-api
         META_WHATSAPP_ACCESS_TOKEN, META_WHATSAPP_PHONE_NUMBER_ID,
         META_WHATSAPP_BUSINESS_ACCOUNT_ID, META_WHATSAPP_APP_SECRET,
         META_WHATSAPP_VERIFY_TOKEN
       (the API refuses to start in production if any are missing).
    d. In Meta: WhatsApp > Configuration > Webhook:
         Callback URL = <API_URL>/api/v1/webhooks/whatsapp
         Verify token = the string from step b; subscribe to "messages".
    e. The Meta test number can message only 5 pre-approved recipients; a
       production number needs Meta business verification.

OPTION C - Integrate from THEIR existing software through the API
  Current limitation (be upfront with them): API keys can be created and
  revoked (Settings > API keys) but no endpoint accepts them for
  authentication yet, so a third-party system cannot call the API directly.
  Interim approach: use Option A or B and import their data with the CSV
  import (Customers / Products). Building API-key authentication is the first
  step needed for true system-to-system integration.


PART 6. OPERATIONS CHECKLIST
----------------------------
  - Scheduled jobs: three daily Vercel crons call /api/v1/cron/overdue-sweep,
    /recurring-invoices and /reminders. Vercel sends CRON_SECRET automatically,
    so CRON_SECRET must be set on the API project.
  - Logs:  vercel logs <your-api-domain> --no-follow --level error
  - Telegram not delivering?  1) customer pressed Start via the link?
    2) getWebhookInfo shows no last_error_message?  3) TELEGRAM_BOT_TOKEN set
    on the API project and redeployed?  4) check MessageDelivery rows with
    channel TELEGRAM for the errorMessage.
  - First request after idle can be slow (Neon wakes up); retry once.
  - Rotate any secret that was ever pasted into chat, email or a ticket.
  - Never commit .env files (they are gitignored).
